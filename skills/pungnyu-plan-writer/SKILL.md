# 풍류천재 기획안 작성

PD(정해빈)가 회사 기획안 플랫폼에 옮겨 적을 **기획안 텍스트**를 채팅으로 써 준다. 디자인 파일이나 HTML은 만들지 않는다. 옮겨 적기 쉽게 섹션 순서와 "라벨: 값" 형태를 지키는 것이 가장 중요하다.

## 1. 입력 파악

필요한 것은 두 가지다. 메시지에서 찾고, 없을 때만 짧게 묻는다.
- **코너**: 치트키(요리 레시피) / 풍류유람기(지역 맛집 투어) / 마감주(요리 + 안주 먹방)
- **이번 회차 주제**: 메뉴(치트키·마감주) 또는 지역·방문지(풍류유람기)

선택 정보(촬영 날짜, 콜타임, 장소, 촬영감독, 발행일, 주차, 제작 일정, 가게명, 브랜드·광고상품, PD 메모)는 주어진 것만 쓴다. 이것 때문에 되묻지 말고 바로 작성한다. 비어 있는 칸은 아래 규칙대로 `⬜ 미정`으로 남기면 PD가 나중에 채운다.

## 2. 참고 자료 읽기

1. `references/channel.md`: 채널, 출연자 말투, 내러티브. 항상 읽는다.
2. `references/<코너>.md`: 해당 코너의 구성, 고정 멘트, 지난 회차 값, 실제 기획안 발췌. 해당 코너 파일만 읽는다.
3. 사용자가 지난 기획안(PDF·이미지·텍스트)을 첨부했다면, 코너 파일보다 그 기획안의 구성·분량·톤을 우선해서 따른다. 이미지로만 된 PDF면 페이지를 이미지로 보고 읽는다. 내용(메뉴·날짜·사람·가게)은 복사하지 않는다.

## 3. 작성 규칙

이 규칙들은 셰프님과 제작진이 기획안을 그대로 믿고 촬영 준비를 하기 때문에 있다. 지어낸 값 하나가 섭외나 장보기 실수로 이어진다.

- **모르는 값은 지어내지 않는다** → `⬜ 미정`. 날짜, 장소, 사람 이름, 가게명, 가격, 연락처, 광고주 메시지가 특히 그렇다.
- 지난 회차 값을 참고로 보여 줄 땐 → `⬜ 미정 (지난번엔 OOO)`. 값은 코너 파일의 "지난 회차 값"에 있다.
- 셰프 확인이 필요한 내 제안(시식 아이디어, 레시피 디테일, 연출, 가게 후보)에는 `(제안)`을 붙인다.
- 계량·부위·시간 같은 정확한 수치는 쓰지 말고 "정확한 계량 후 안내"라고 적는다. 그 항목은 맨 끝 셰프 확인 목록에 올린다.
- 대사 예시는 조서형 셰프 말투(channel.md)로, 실제로 말하듯 쓴다. 코너 고정 멘트는 그대로 넣는다.
- PD 질문은 시청자 눈높이에서, 따라 하다 막히는 지점 위주로 쓴다(왜 그래요? 언제 넣어요? 대체 재료는? 보관은? 실패하면?).
- 지역 음식이면 지역 비교 질문을 넣는다(서울식 vs 경상도식, 서해 vs 남해 등).
- 재료 소개 파트에는 대체 재료를 꼭 언급한다.
- 타임테이블은 조리·체류 시간이 긴 것을 먼저 둔다. 콜타임이 없으면 시각 대신 경과 시간(0:00~0:30)으로 쓴다.

## 4. 출력 형식

아래 순서와 라벨을 그대로 쓴다. 표(|)는 쓰지 않는다. 플랫폼에 붙여 넣을 때 깨지기 때문이다. 코너 파일에 표지 추가 항목(예: 마감주의 영상포맷·브랜드명·광고상품)이 있으면 표지 끝에 같은 형식으로 덧붙인다.

```
# [제목(가안)]
(코너 · 이번 회차 주제)

## 표지
제목(가안): ...
다른 안 1: ...
다른 안 2: ...

채널명: 풍류천재조서형
담당 PD: 정해빈
촬영감독: ...
발행일: ...
촬영 날짜: ...
촬영 장소: ...
콜타임: ...
주차 안내: ...

## 타임테이블
09:40–10:00  내용
...

## CONTENT NOTE
채널 내러티브와의 연결성
(계절감 + "나도 해 먹고 싶다 / 가 보고 싶다"는 마음, 2~3문장)

시청자에게 줄 수 있는 것
· (3~4개)

기대하는 시청자 반응
· "예상 댓글" 등 OO 반응 (4~5개: 따라 하기 / 꿀팁 공감 / 지역·추억 공감 / 먹방 반응 / 시리즈 요청)

썸네일 후보
1안  문구 — 화면 구성
2안  ...
3안  ...

출연자의 역할
...

PD의 역할
...

## 썸네일 레퍼런스
⬜ 미정 (제안 방향: ...)

## FLOW / S#1 [신 제목]
- 이 신에서 다룰 포인트 불릿

대사 예시
[ 블록명 ]   ← 블록이 2개 이상일 때만
...

PD 질문 혹은 역할
[ 블록명 ]
· ...

이미지: ⬜ 미정 (필요한 컷 설명)

(S#2, S#3 ... 코너 구성대로 반복)

## 샷
(코너 파일의 샷 목록을 그 라벨 그대로 한 줄씩, 이번 회차에 맞는 장면을 덧붙여서)
main cam: ...
sub 1: ...

## PRODUCTION
최종 체크
✓ 채널 코어 내러티브  (이번 회차에 맞는 한 문장)
✓ 커뮤니티 구축  ...
✓ 출연자·제작진의 목표  ...

검토 상태: ⬜ 미정

## 제작 일정
기획안 1차 전달: ...
기획안 피드백: ...
촬영일: ...
발행일: ...

---
## 비워 둔 항목
· (⬜ 미정으로 둔 모든 항목, 표지부터 순서대로)

## 셰프님 확인이 필요한 부분
· 항목 — 왜 확인이 필요한지
```

기획안 본문 앞뒤에 긴 설명을 붙이지 않는다. 끝에 한 줄로 "가게명/날짜 등 알려 주시면 채워서 다시 정리해 드릴게요" 정도만 덧붙인다.

## 5. 수정 요청이 오면

"S#2 질문 더", "제목 바꿔", "촬영 날짜 12/3으로" 같은 요청은 해당 부분만 고쳐서 보여 준다. 사용자가 전체를 다시 달라고 하면 같은 형식으로 전체를 다시 낸다. 새로 받은 값은 `비워 둔 항목`에서 지운다.
